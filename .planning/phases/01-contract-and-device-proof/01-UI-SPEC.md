# Phase 01 — UI Design Contract

> Visual and interaction contract for the portrait-only SwiftUI candidate device-proof surface. Generated by the gsd-ui-researcher generic-agent workaround; verification and physical-device evidence remain separate.

---

## Scope and Authority Boundary

This contract covers only the Phase 1 native iPhone candidate used to prove permissions, ARKit tracking and planes, portrait capture gating, world-epoch correction or quarantine, one minimal hash-valid journaled FramePacket, and privacy-safe internal evidence export.

It does not add or imply place, replace, remove, restore, target selection, asset browsing, provider status, a production compositor, continuous recording, upload, sharing, model/network behavior, Mode B0, or physical gate success. ARKit remains active when the phone is held sideways. Capture stays unavailable until the phone returns to portrait and every independent prerequisite is ready. The base-device path never requires rear LiDAR.

Two compile-time surfaces share one app target:

| Build | Root surface | Allowed content | Prohibited content |
|---|---|---|---|
| Release | `CandidateSeedView` | Required camera permission, session, orientation, tracking/plane, quarantine, capture availability, capture result, and recovery coaching | Optional microphone proof control, diagnostic checklist, raw facts, export controls, evidence IDs/digests, gate-control UI, edit/provider/compositor controls |
| Debug/internal | `DiagnosticChecklistView` around the same candidate session | Every Release behavior plus independent checklist facts and sanitized evidence export | Raw room bytes, raw logs, device UUID, team/account ID, user path, signing material, automated GREEN/WAIVED controls |

Release exclusion is compile-time, not a hidden runtime flag. A Release build must contain none of the Debug diagnostic/export accessibility identifiers or controls. The candidate is not called the Mode A production seed unless separate real GATE-013 evidence is GREEN and human-signed.

## Design System

| Property | Value |
|----------|-------|
| Tool | Native SwiftUI; no web design-system tool |
| Preset | Not applicable |
| Component library | Apple SwiftUI controls and containers only |
| Icon library | SF Symbols supplied by the pinned Xcode/iOS SDK |
| Font | San Francisco through SwiftUI system text styles |
| Appearance | Dark, camera-legible device-proof chrome; no Liquid Glass requirement |
| Localization | SwiftUI-localizable string literals/String Catalog when created; English is the canonical source language |

No existing native UI or token set was present when this contract was authored. Use the values below as Phase 1-local tokens; do not scaffold a cross-product design system. Prefer native `Button`, `ProgressView`, `Label`, `ScrollView`, `safeAreaInset`, `alert`, and system permission/settings flows. Tappable content must use `Button`, not `onTapGesture`.

## Spacing Scale

Declared values are base points and multiples of four:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4pt | Icon-to-label micro-gap; status dot-to-text gap |
| sm | 8pt | Compact status-row spacing; related inline controls |
| md | 16pt | Default horizontal inset, card padding, control gap |
| lg | 24pt | Bottom action-tray padding and major section separation |
| xl | 32pt | Permission/blocked-state illustration-to-heading separation |
| 2xl | 48pt | Sparse full-screen state separation only |
| 3xl | 64pt | Reserved; do not use in the compact checklist unless the surface is intentionally empty |

Exceptions:

- Interactive controls have a minimum 44×44pt hit area; this accessibility minimum is not a spacing token.
- Hairline separators and focus outlines may render at one physical pixel; they are borders, not spacing.
- Safe-area insets are system supplied. Never replace them with fixed top/bottom values.
- At accessibility Dynamic Type sizes, scale icon/control dimensions only where needed for legibility, but keep page/card margins at 16pt so the portrait viewport remains usable.

Layout rules:

- Use one full-screen portrait root. The AR camera is the background only after camera authorization; otherwise render the dominant fallback surface.
- Apply a 16pt horizontal safe-area inset to all status, coaching, and action content. Use 8pt between stacked status rows and 24pt between the coaching panel and action tray.
- Release uses a top status capsule/panel and bottom action tray. Neither may cover the central checkerboard/plane-observation region more than necessary.
- Debug uses a vertically scrolling checklist. It must fit the same portrait viewport without horizontal scrolling, clipped controls, or a fixed-height text container.
- At large accessibility sizes, change horizontal action groups to vertical full-width controls with 8pt separation. Never shrink type or truncate the primary action to preserve a row.

## Typography

Use exactly four base sizes and exactly two weights. Map them to Dynamic Type-aware system text styles; the point values are reference sizes for visual tests, not fixed-size opt-outs.

| Role | Base size | Weight | Line height | SwiftUI intent | Usage |
|------|-----------|--------|-------------|----------------|-------|
| Label | 13pt | Semibold (600) | 1.25 | `.footnote` | Status names, build marker, compact buttons |
| Body | 17pt | Regular (400) | 1.35 | `.body` | Coaching, explanations, status values |
| Heading | 22pt | Semibold (600) | 1.20 | `.title2` | State title and permission-block heading |
| Display | 28pt | Semibold (600) | 1.15 | `.title` | Initial candidate title only |

Typography constraints:

- Use sentence case. Do not force uppercase through a runtime text transform.
- Essential headings, coaching, errors, and button labels wrap to multiple lines; no ellipsis or one-line limit.
- Monospaced text is Debug-only and limited to short sanitized case/build suffixes. Never expose a full device ID, digest, path, team/account value, or signing material.
- Status row names may remain 13pt semibold; their values are 17pt regular and move below the name when horizontal space is insufficient.
- Support every Dynamic Type size through the largest accessibility category. At accessibility sizes, the Release surface scrolls below the camera/status region and keeps the primary action reachable.
- User-facing strings are localizable as whole phrases. Never assemble sentences from independently localized fragments; layout uses leading/trailing rather than left/right.

## Color

The 60/30/10 split applies to UI chrome, not to the live camera pixels. The camera remains the photoreal background and is never globally recolored.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0B0F14` | Permission/blocked fallback background; opaque fallback behind camera failure; high-legibility scrim |
| Secondary (30%) | `#171D24` at 94% opacity | Status/coaching cards and bottom action tray |
| Accent (10% max) | `#4DA3FF` | Enabled primary CTA fill, keyboard/VoiceOver focus emphasis, selected Debug section only |
| Accent-on text | `#0B0F14` | Primary CTA label/icon on the accent fill |
| Primary text | `#F5F7FA` | Headings, CTA text where contrast passes, primary status copy |
| Secondary text | `#B7C0CA` | Explanatory copy and noncritical metadata |
| Success fact | `#30D158` | Locally observed ready fact only; never a substitute for GATE GREEN |
| Warning/coaching | `#FFD60A` | Orientation, limited tracking, no-plane, and quarantine emphasis |
| Destructive/failure | `#FF453A` | Permission denial, failed capture, invalid correction, and RED fact only |
| Neutral/pending | `#8E8E93` | Not determined, unavailable, waiting, and UNRUN facts |

Accent is reserved for the currently enabled primary action, focus emphasis, and one selected Debug section marker. It is not applied to every link, status, icon, or card.

Color constraints:

- Text and meaningful icons meet 4.5:1 contrast against their immediate panel; large display text meets 3:1. The panel behind camera-overlay text is at least 88% opaque when contrast cannot be measured from camera pixels.
- Every success, warning, pending, and failure state includes a distinct SF Symbol and text label. Color alone never communicates readiness or gate state.
- A local checkmark means only that the app currently observed that fact. The words `Gate passed`, `GREEN`, or `Production seed` are forbidden on the Release surface before separately verified human evidence permits them.
- Use no gradients, decorative glow, translucency-heavy glass treatment, or continuous status pulse in Phase 1.

## Visuals and Interaction

### Release composition

1. **Status panel (top safe area):** app identity `ReRoom device check`, current session state, and—when relevant—one concise coaching line. It must remain legible over the live camera.
2. **Observation region (center):** live AR camera only. Phase 1 adds no rendered furniture, target mask, reveal, shadow, edit reticle, or production compositor overlay. A minimal plane/checkerboard proof overlay is allowed only when explicitly required by the GATE-002 test procedure and must be labeled `Device check overlay`.
3. **Action tray (bottom safe area):** exactly one primary action appropriate to the state plus at most one secondary recovery/settings action. Disabled controls remain visible when their blocker explanation is useful.
4. **Transient result:** a success/failure card appears above the action tray and remains until dismissed or the next attempt; do not rely on a disappearing toast for evidence-critical status.

### Debug/internal composition

Debug launches the same session behavior with a compact checklist sheet or root containing these independent rows in this order:

1. Camera permission
2. Optional microphone permission
3. Physical orientation
4. ARKit tracking
5. Horizontal planes
6. Vertical planes
7. World epoch / correction / quarantine
8. Packet image and metadata durability
9. Authoritative journal and network-eligible visibility
10. Build/signing/capability facts
11. Current gate record state (`UNRUN`, `RUNNING`, or `RED` from automation; human-bound GREEN is display-only if loaded from verified signed evidence)

Each row shows label, state icon, plain-language value, and one short reason when blocked. Rows do not collapse independent states into an aggregate `ready` badge. The Debug-only `Export sanitized evidence` button is last and uses the native share/export presentation only after validation and atomic write succeed.

### Controls inventory

| Control | Build | Availability | Exact label | Contract |
|---|---|---|---|---|
| Camera permission | Release + Debug | Camera `notDetermined` | `Allow Camera Access` | Requests camera authorization once; never starts capture before grant |
| Optional microphone permission | Debug only | Microphone `notDetermined`; secondary | `Check Microphone Access` | Records GATE-013 authorization readiness only; never records audio and never gates visual/AR/typed-tap availability; absent from Release because Phase 1 ships no microphone feature |
| Settings recovery | Release + Debug | Camera denied/restricted | `Open Settings` | Opens system settings; no repeated permission-loop button |
| Test capture | Release + Debug | Camera granted + portrait + session running + tracking normal + epoch usable/not quarantined | `Capture Test Frame` | Captures one bounded attempt; no continuous recording, upload, or server acknowledgement |
| Capture retry | Release + Debug | Previous attempt rejected/failed and prerequisites now allow retry | `Try Capture Again` | Creates a new attempt; does not revive a rejected snapshot |
| Restart session | Release + Debug | Tracking unavailable or explicit quarantine recovery | `Restart Device Check` | Keeps saved evidence; if an attempt is active, requires the confirmation copy below |
| Diagnostics | Debug only | Always after app launch | `Diagnostics` | Opens the internal checklist; identifier/symbol/control absent from Release |
| Evidence export | Debug only | Only after sanitized evidence validates | `Export Sanitized Evidence` | Remains unavailable while validation fails and identifies the failed checklist row; after correction and successful revalidation, exports validated allowlisted facts only and never changes gate state |

All actions are native `Button` controls with a 44×44pt minimum target. The enabled primary action is full width. Disabled controls expose the blocker in adjacent text and in their accessibility value; do not provide only a disabled button with no explanation.

### Motion and feedback

- State changes use an optional 0.2-second opacity transition scoped to the coaching/result card. There are no camera-linked layout animations.
- Honor Reduce Motion by replacing transitions with immediate changes. Critical state is never communicated by animation.
- A bounded `ProgressView` is allowed for permission requests, AR session initialization, and the single capture attempt. Never show an indefinite spinner without explanatory text.
- Optional sensory feedback may mark a successful local save or failed attempt, but it cannot be the only feedback and must not fire for every AR frame/plane update.

## State and Transition Contract

State priority is fail-closed: camera restriction/denial → physical landscape → session unavailable → epoch quarantine → tracking limited/no planes → eligible portrait capture. A lower-priority ready fact never hides a higher-priority blocker.

| State / trigger | Visible title and body | Primary / secondary controls | Accessibility and test boundary |
|---|---|---|---|
| App launch; camera `notDetermined` | `Camera access is required` / `ReRoom needs the camera to run this device check. No frame is captured until you allow access.` | `Allow Camera Access` | Focus starts on heading; `release.permission.camera`; no camera session/capture before grant |
| Camera request in flight | `Waiting for camera permission` / `Complete the system permission prompt.` | Primary disabled with progress; microphone action unavailable during system prompt | Announce once; no repeating status; `release.permission.camera.pending` |
| Camera denied/restricted | `Camera access is off` / `Turn on camera access in Settings to run tracking and capture a test frame.` | `Open Settings`; no capture | Failure icon + text; `release.permission.camera.blocked`; no AR/capture side effect |
| Debug: microphone `notDetermined` with camera ready | Compact checklist row: `Microphone check not run` / `Optional for this device check. It never records audio and does not block the camera.` | `Check Microphone Access`; capture remains independently available | `debug.permission.microphone`; never precedes capture in VoiceOver order; row/control absent from Release |
| Debug: microphone denied/restricted | `Microphone check unavailable` / `Camera tracking and test capture still work. No audio is recorded.` | No microphone retry loop; capture unchanged | Warning/neutral, not failure for camera; tests assert unchanged visual readiness and Release exclusion |
| Camera granted; AR session initializing | `Starting AR tracking` / `Keep the phone upright and point it toward visible floor.` | Capture disabled | Progress plus text; `release.status.session`; session start never waits for network/model |
| Physical device held landscape | `Rotate to portrait` / `Tracking stays active. Return to portrait to capture a test frame.` | Capture visible but disabled | Assertive one-time announcement on transition; `release.coaching.orientation`; AR session-running fact remains true |
| Rotation occurs during capture | `Capture stopped` / `The phone turned sideways. Return to portrait and try again.` | `Try Capture Again` disabled until portrait | Persistent error/result card; old attempt never publishes; session remains active |
| Tracking limited | `Move slowly to restore tracking` / Reason-specific copy: `Keep the floor in view and avoid fast movement.` or `Point toward a textured, well-lit area.` | Capture disabled; optional `Restart Device Check` only if recovery does not progress | State icon + reason; update/announce only when reason category changes, not every frame |
| Tracking unavailable | `Tracking is unavailable` / `Restart the device check. Saved evidence stays on this iPhone.` | `Restart Device Check` | `release.status.tracking.unavailable`; no capture or commit controls |
| Tracking normal, zero planes | `Look for a floor or wall` / `Move the phone slowly so ARKit can observe a surface.` | Capture disabled for the plane-proof path | Zero-plane state is explicit; `release.status.planes.empty` |
| One plane type observed | `Surface check in progress` / `A floor` or `A wall has been observed. Continue until the required device-check surfaces are reported.` | Capture eligibility follows the active test procedure; never imply both types | Singular/localized copy; horizontal and vertical facts remain separate in Debug |
| Epoch change with valid directed correction | `Alignment updated` / `The device check can continue with the new world frame.` | Capture becomes eligible only after all other prerequisites pass | Announce once; display new version only in Debug; Release exposes no transform/digest |
| Epoch change without valid alignment | `Alignment needs recovery` / `Capture is paused because the world frame could not be verified. Restart the device check.` | `Restart Device Check`; capture disabled | Warning/failure icon + `Quarantined` accessibility value; `release.status.epoch.quarantined` |
| Eligible portrait state | `Ready to capture a test frame` / `Hold the phone steady. This saves one test frame on this iPhone.` | `Capture Test Frame` | Primary receives focus after the status announcement; no word `record` or `upload` |
| Capture in progress | `Capturing test frame` / `Keep the phone upright and steady.` | Primary disabled with bounded progress | `release.status.capture.inProgress`; cancellation occurs only through invalidating state/restart |
| Hash-valid journaled packet visible locally | `Test frame saved` / `The frame and its metadata were verified and saved on this iPhone. Nothing was uploaded.` | `Capture Test Frame` may create a fresh attempt | Success icon + text; never say GATE passed; `release.status.capture.saved` |
| Durability/hash/journal failure | `Test frame wasn’t saved` / `No incomplete frame was published. Check device storage and try again.` | `Try Capture Again`; restart if policy requires | Error remains until action; no partial-success state; `release.status.capture.failed` |
| Debug: sanitized evidence validation failed | `Evidence wasn’t exported because validation failed. No file was shared. Review the failed check, then try exporting again.` | `Export Sanitized Evidence` remains visible but unavailable until the failed check is corrected and revalidation passes | Persistent failure icon + text identifies the failed checklist row; `debug.action.exportEvidence` remains disabled; no file is written and no share sheet appears |

Restart confirmation while an attempt is active:

- Title: `Restart device check?`
- Message: `Restarting stops the current test frame. Saved evidence stays on this iPhone.`
- Confirm: `Restart Device Check`
- Cancel: `Keep Checking`

No Phase 1 control deletes durable evidence or canonical history. There is no destructive action in this surface.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Candidate display title | `ReRoom device check` |
| Build-status qualifier | `Candidate — physical verification pending` |
| Primary CTA | `Capture Test Frame` |
| Camera permission CTA | `Allow Camera Access` |
| Optional microphone CTA | `Check Microphone Access` |
| Empty camera heading | `Camera access is required` |
| Empty camera body | `ReRoom needs the camera to run this device check. No frame is captured until you allow access.` |
| Empty plane heading | `Look for a floor or wall` |
| Empty plane body | `Move the phone slowly so ARKit can observe a surface.` |
| Landscape coaching | `Rotate to portrait` / `Tracking stays active. Return to portrait to capture a test frame.` |
| Generic tracking error | `Tracking is unavailable. Restart the device check. Saved evidence stays on this iPhone.` |
| Generic capture error | `Test frame wasn’t saved. No incomplete frame was published. Check device storage and try again.` |
| Capture success | `Test frame saved. The frame and its metadata were verified and saved on this iPhone. Nothing was uploaded.` |
| Quarantine error | `Alignment needs recovery. Capture is paused because the world frame could not be verified. Restart the device check.` |
| Debug export success | `Sanitized evidence is ready to export.` |
| Debug export failure | `Evidence wasn’t exported because validation failed. No file was shared. Review the failed check, then try exporting again.` |
| Destructive confirmation | None; session restart uses the non-destructive confirmation defined above |

Copy rules:

- Say `test frame`, not `recording`, unless a future phase explicitly introduces continuous recording.
- Say `saved on this iPhone`, not `uploaded`, `synced`, or `server acknowledged`.
- Say `camera tracking`, `ARKit tracking`, or `surface observed`; never say `LiDAR scan`, `3D scan`, `room model`, or `physical validation`.
- Say `candidate` and `verification pending` until the separate human evidence lifecycle permits a stronger statement.
- Debug gate-state copy uses the exact canonical words `UNRUN`, `RUNNING`, `GREEN`, `RED`, and `WAIVED_BY_HUMAN`. Automation exposes no action that selects GREEN or WAIVED_BY_HUMAN.
- Error copy states what failed, what remains safe, and the next action. Do not expose paths, IDs, stack traces, hashes, signing details, or raw errors in Release.

## Accessibility Contract

- VoiceOver order is: state heading → coaching/body → current status value → primary action → secondary action. Debug reads checklist rows in the fixed order above, then export.
- Meaningful state changes announce once. High-rate AR frame, plane extent/count, pose, and timestamp changes never trigger announcements. Coalesce repeated limited-tracking reasons.
- Every icon has an adjacent text label. Decorative SF Symbols are hidden from the accessibility tree when their meaning is already included in the combined row label.
- Status rows expose a combined label and value, for example `Camera permission, allowed` or `World alignment, quarantined`. Do not expose raw enum spellings without understandable text.
- Disabled capture exposes a reason in the visible coaching panel and accessibility value. The user must not have to discover a disabled button to learn the blocker.
- All controls meet 44×44pt targets and work with Voice Control labels matching visible labels. No gesture-only action exists.
- Dynamic Type supports the largest accessibility category; content scrolls vertically, cards expand, and button groups stack. Essential copy never clips or truncates.
- Text/panel contrast meets the color rules above. Differentiate Without Color remains usable because every state has symbol, label, and explanation.
- Reduce Motion removes transitions. Progress remains understandable through text. No flashing, pulsing, or parallax effect is allowed.
- The camera observation region does not receive VoiceOver focus unless the explicit checkerboard proof overlay exposes a single `Device check camera view` element; individual plane visuals are not separately focusable.
- Permission and error copy is localizable as complete phrases. Test with a pseudo-localized expansion of at least 40% and with right-to-left layout; status/action layout must reflow without semantic reversal.
