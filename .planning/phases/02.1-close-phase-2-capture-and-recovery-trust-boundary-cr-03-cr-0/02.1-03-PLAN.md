Add only the filesystem capabilities actually missing for owned staging cleanup and atomic first-writer pointer arbitration. Atomic pointer publication must be first-writer-wins: install the fully fsynced staged pointer as the final visibility operation; if a pointer already exists, bounded-read and compare it, returning reuse for the same verified generation or `publication_conflict` for a different generation. <threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| RecoveryGenerationCandidate -> staging | Candidate members must remain bound as one closed result while writes and crashes occur. |
| Staged generation -> active pointer | Visibility crosses from uncommitted bytes to replay authority at one filesystem commit. |
| Concurrent publishers -> shared source root | Two valid processes may race and must not overwrite or delete one another's result. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-02.1-05 | Tampering | Generation/member publication | high | mitigate | Task 1 binds every member in a canonical inventory and verifies stage/final bytes before pointer visibility. |
| T-02.1-06 | Denial of service | Concurrent publisher cleanup | high | mitigate | Task 2 uses first-writer arbitration and deletes only invocation-owned staging paths. |
| T-02.1-07 | Spoofing | Active pointer/source identity | high | mitigate | Tasks 1-2 bind pointer, source manifest/session identity, generation ID, and inventory digest and reject a different active result. |
| T-02.1-08 | Repudiation | Crash boundary outcome | medium | mitigate | Task 1 records deterministic before/after operation traces and restart verdicts for every durability edge. |
</threat_model>
