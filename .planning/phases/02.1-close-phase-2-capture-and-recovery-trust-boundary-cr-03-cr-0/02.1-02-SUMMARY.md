## Decisions Made

- The stale manifest remains necessary admission evidence but contributes no accepted-prefix projection. The physical global journal is the only recovery ordering authority.
- Event paths are derived by prior event count and frame paths by stable frame identity. Packet-declared image paths are accepted only after frozen schema validation and exact byte/hash binding.
- Candidate construction is deterministic and source-preserving. Its optional invalid suffix is bounded evidence, not an independently published quarantine artifact.
- Recovery materializes only an isolated test/verification root internally and passes it through the sole verifier before returning; visibility remains reserved for Plan 03.
- Nullable `previous_durable_frame_id` retains its frozen meaning. The first frame must be null; later null values remain valid, and any non-null value must bind exactly to the prior durable frame.

## Threat Model Closure

- **T-02.1-03 (journal/member tampering): mitigated.** Canonical contiguous journal entries, stable IDs, deterministic paths, exact member bytes, record hashes, schema validation, lifecycle adjacency, and independent archive verification all precede candidate return.
- **T-02.1-04 (stale-manifest repudiation): mitigated.** Tests prove the stale three-record manifest cannot hide the valid six-record physical prefix, which reconstructs as one frame and five events.
- **T-02.1-05 (unbounded scanning): mitigated.** Journal bytes, line/member counts, individual members, aggregate bytes, and invalid suffix evidence are bounded before decoding or allocation.
- **T-02.1-06 (diagnostic disclosure): accepted as planned.** Candidate evidence remains internal and contains only bounded suffix bytes plus canonical hashes/counts; production code does not log room evidence.

## Deviations from Plan

### Authorized verifier compatibility corrections

**1. Exact fsynced-frame recovery exposed an over-strict recovered lifecycle rule**

- **Found during:** Task 1 GREEN independent candidate verification
- **Issue:** A prefix ending immediately after the record-first writer's durable frame journal append has selected and image-durable events plus the frame record, but the verifier required the later network-eligible event.
- **Fix:** For `recovered_prefix`, required the exact contiguous lifecycle through image durability when a frame record exists, while retaining stronger open/finalized rules and rejecting skipped, duplicated, inverted, or later contradictory stages.
- **File modified:** `ios/Packages/ReRoomContracts/Sources/ReRoomCaptureCore/ArchiveVerifier.swift`
- **Verification:** Exact-frame-boundary recovery verifies and replays; the adjacent invalid-lifecycle corruption case fails closed.
- **Committed in:** `3741e68`

**2. Frozen multi-frame writer output exposed an over-strict optional-link rule**

- **Found during:** Task 2 RED production routing of second-frame fault edges
- **Issue:** CON-001 permits `previous_durable_frame_id` to be a frame ID or null, and the unchanged frozen encoder emits null, but the verifier required a non-null prior-frame link after frame one.
- **Fix:** Retained first-frame null, accepted later null, and required any supplied non-null link to equal the immediately prior durable frame. Capture-sequence ordering remains strict.
- **File modified:** `ios/Packages/ReRoomContracts/Sources/ReRoomCaptureCore/ArchiveVerifier.swift`
