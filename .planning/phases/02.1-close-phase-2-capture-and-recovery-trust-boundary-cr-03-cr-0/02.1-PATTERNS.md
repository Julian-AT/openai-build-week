## Pattern Assignments

### 1. Pinned validator injection and fail-closed capability minting

**Apply to:** archive admission and `VerifiedArchive`.

- `Sources/ReRoomContracts/ContractValidation.swift:4-31` owns the closed schema
  IDs, versions, contract IDs, and pinned SHA-256 values.
- `ContractValidation.swift:101-185` is the immutable, bounded, fail-closed
  validator API with typed verdicts.
- `ContractValidation.swift:280-297` serializes the third-party validator and
  documents the `@unchecked Sendable` safety invariant.
- `Sources/ReRoomCaptureCore/FramePacketEncoder.swift:126-136` injects one
  configured `ContractValidator` into a `Sendable` value.
- `FramePacketEncoder.swift:238-253` validates canonical document bytes plus
  exact payload bytes and maps every non-accept verdict to a typed error.

Copy the dependency shape, not the current recovery subset:

```swift
public struct FramePacketEncoder: Sendable {
    public let validator: ContractValidator
    public init(validator: ContractValidator, profile: FramePacketEncodingProfile) { ... }
}
```

Admission must validate complete CON-002 bytes, then every exact CON-001 packet
with its payload, then enforce D-03 cross-record bindings. Only that combined
operation constructs the opaque capability. Bind source identity, immutable
generation, manifest/inventory digests, and member descriptors. Re-read through
bounded non-symlink paths and rehash at consumption. Do not keep
`RecoveryArchiveReader` (`CaptureRecovery.swift:412-685`) as a second authority;
use its binding checks only as implementation input after schema acceptance.

### 2. Synchronous filesystem seam with deterministic fault edges

**Apply to:** reconstruction, generation publication, pointer update, restart,
and race tests.

- `Sources/ReRoomCaptureCore/CaptureFileSystem.swift:39-70` defines stable
  operation kinds and `@Sendable` observers.
- `CaptureFileSystem.swift:72-84` is the narrow synchronous I/O protocol.
- `CaptureFileSystem.swift:92-109` injects before/after observers under one
  non-reentrant owner.
- `CaptureFileSystem.swift:132-243` wraps create/write/fsync/append/replace/
  rename on both sides of each durability boundary.
- `CaptureFileSystem.swift:245-314` performs bounded regular-file reads and
  archive-relative resolution.

Keep publication synchronous between observed operations so process death can
be injected before and after every named edge. Extend the seam only for concrete
missing operations. Cleanup receives only the invocation's unique staging path;
it never targets a final generation, pointer, archive, or quarantine result.

### 3. Content-addressed generation and pointer-last visibility

**Apply to:** recovered archive, invalid suffix, quarantine metadata, and their
inventory as one committed result.

- `Sources/ReRoomTransactionCore/TransactionStore.swift:152-176` injects
  filesystem/contract adapters and validates before mutation.
- `TransactionStore.swift:178-204` writes generation members before pointer
  activation and reuses a matching generation.
- `TransactionStore.swift:212-280` follows only the active pointer, verifies the
  inventory and every member, then performs semantic validation.
- `TransactionStore.swift:464-523` binds member name, byte count, and hash in a
  canonical inventory; its digest becomes generation identity.
- `TransactionStore.swift:559-574` rejects non-canonical/lossy round trips.
- `Sources/ReRoomTransactionCore/TransactionFileSystemAdapter.swift:18-59`
  fsyncs members, generation, parent, then the active pointer and root.

Transfer this ordering:

```text
validate → stage/write/fsync all members → inventory → verify stage
→ rename immutable generation → fsync parent → replace/fsync pointer last
```

Strengthen the analog: it currently creates directly at the final digest path
(`TransactionStore.swift:189-203`) and uses a replaceable pointer. Phase 02.1
requires unique staging, rename arbitration, identical-winner reuse, explicit
`publication_conflict` for a different active result bound to the same source,
and loser cleanup that cannot delete a winner. Never use last-writer-wins.

### 4. Parameterized mutation, crash, restart, and replay proof

- `CaptureRecoveryTests.swift:9-38` parameterizes finalized/recovered fixtures
  and proves source immutability.
- `CaptureRecoveryTests.swift:40-104` distinguishes terminal suffix salvage from
  fatal first/interior/adjacency corruption.
- `CaptureRecoveryTests.swift:106-170` provides enumerated mutations,
  idempotency snapshots, and rollback assertions.
- `ReplayCoreTests.swift:9-53` pins ordered replay counts and digests;
  `:97-135` covers concurrent readers and fail-closed mutations.
- `CaptureCrashMatrixTests.swift:9-75` has the writer fault matrix, but its
  `scanDurablePrefix` oracle is the CR-04 testing defect. Route crashed bytes
  through production recovery, verifier, and capability-only replay.
- `CaptureCrashMatrixTests.swift:77-118` is the current production recovery
  probe; `:275-358` enumerates durability edges, including fsynced journal data
  beyond a stale manifest; `:517-571` is the occurrence-aware fault controller.
- `TransactionStoreCrashTests.swift:9-37,157-195` is the closest pointer-last
  process-death matrix; `:217-257` supplies its deterministic controller and
  `:260-403` models durable state after restart.

Preserve existing Swift Testing style: parameterized `@Test(arguments:)`,
`#require` prerequisites, exact typed errors, isolated roots, and observer/barrier
races rather than sleeps. CR-03 mutations must recompute outer digests so schema
or binding rejection is causal. CR-04 must compare production replay to the
physically fsynced prefix. CR-12 must cover every generation/pointer edge and
repeated two-publisher rendezvous races.

## Shared Patterns and Gaps

- Translate stable errors once, following `ReplayCore.swift:121-139`; preserve
  `publication_conflict` distinctly.
- Use canonical JSON and `CanonicalJSON.sha256Hex` as in
  `TransactionStore.swift:464-523` and `FramePacketEncoder.swift:238-267`.
- Admission owns URLs; replay owns only verified-capability transformation. The
  raw entry at `ReplayCore.swift:29-39` is the seam to remove.
- No complete existing analog proves verifier-only capability construction,
  post-verification substitution defense, or same/different-generation race
  semantics. These require explicit new design and tests; a boolean verdict,
  public initializer, or the current two-rename recovery is insufficient.
