# Phase 02.1: Close Phase 2 capture and recovery trust boundary — CR-03 CR-04 CR-12 - Context

**Gathered:** 2026-07-19
**Status:** Ready for planning

<domain>
## Phase Boundary

Close exactly the three foundational Phase 2 recovery defects identified as
`CR-03`, `CR-04`, and `CR-12`: untrusted `.rrcap` input must pass the pinned
CON-001/CON-002 schemas and all cross-record bindings before replay; recovery
must preserve every physically fsynced record in the last valid contiguous
global-journal prefix even when the open manifest projection is stale; and a
recovered archive plus its quarantine evidence must publish atomically and
remain correct under process death, repeat recovery, and concurrent publishers.

This phase repairs the existing `FR-CAPTURE-001`, `FR-B0-001`,
`NFR-REPLAY-001`, `NFR-CONTRACT-001`, `NFR-RESILIENCE-001`, and
`SEC-CONSENT-001` implementation boundary without changing their meaning or the
frozen 1.0 contracts. It does not close the other findings in `02-REVIEW.md`,
does not regenerate physical/human evidence, and cannot by itself mark Phase 2,
`GATE-001`, or milestone v1.0 complete.

</domain>

<decisions>
## Implementation Decisions

### Trusted archive boundary
- **D-01:** `ReplayCore` accepts only an opaque `VerifiedArchive` capability.
  Its initializer is unavailable outside the pinned archive verifier; a raw
  filesystem URL is never sufficient authority to enter replay.
- **D-02:** The capability binds the canonical source identity, immutable
  content-addressed recovery generation, manifest and inventory digests, and
  verified record descriptors. The verifier performs complete eager validation;
  replay then uses bounded non-symlink reads and rechecks each exact member hash
  at consumption time so post-verification file substitution cannot inherit the
  prior verdict.
- **D-03:** One injected fail-closed archive verifier owns the trust policy. It
  reuses the pinned `ContractValidator` for the complete CON-002 manifest and
  every exact CON-001 FramePacket, then enforces the contract-owned session,
  world epoch/version, identity, sequence, lifecycle, image/payload,
  idempotency, journal, event, projection, inventory, path, and digest bindings.
  The current hand-written subset is not retained as an alternate authority.
- **D-04:** A source manifest that fails the frozen contract is rejected and
  retained only as quarantined raw evidence; recovery never interprets unknown
  fields or versions best-effort. Prefix salvage is available only when the
  source root is contract-valid and open/incomplete and the physical journal
  proves a valid prefix followed by a terminal incomplete or corrupt tail. A
  generated recovered manifest and all included records must independently pass
  the same verifier before publication or replay.

### Durable-prefix reconstruction
- **D-05:** Preserve the existing record-first writer ordering and repair
  recovery by scanning the bounded physical `journal/global.jsonl` from sequence
  zero. The last independently verified contiguous physical prefix is authority;
  a stale open-manifest copy cannot truncate a later fsynced journal record.
- **D-06:** Reconstruct `accepted_frame_order`, `events`, inventory membership,
  per-type sequences, durable journal sequences, final sequence, and replay
  input digest from journal entries and their exact referenced packet/event
  bytes. Never merge in or prefer a stale manifest projection merely because it
  is self-consistent.
- **D-07:** Recover only a provably terminal incomplete/corrupt suffix. A gap,
  duplicate, reorder, later valid record after a fault, reference contradiction,
  or other evidence of interior corruption fails closed instead of skipping,
  normalizing, or fabricating records. The original archive remains immutable
  in every case.
- **D-08:** Do not edit or version CON-001/CON-002 and do not replace the capture
  writer persistence model in this phase. Add bounded internal recovery metadata
  only if exact reconstruction is otherwise impossible, and preserve verified
  compatibility with existing Phase 2 archives and fixtures.

### Atomic publication and races
- **D-09:** Publish through one immutable content-addressed recovery generation.
  Write and fsync every generation member and directory, verify the completed
  staged generation, rename it into the generations store, fsync the parent, and
  atomically replace and fsync a small active pointer last. The pointer update is
  the only visibility commit point.
- **D-10:** The generation inventory binds the recovered `.rrcap`, bounded raw
  invalid suffix when one exists, quarantine metadata, source session/manifest
  identity, accepted-prefix journal digest, recovery-format version, member byte
  counts, and member hashes. Archive and quarantine are one committed result,
  never two sequential publications.
- **D-11:** Concurrent or repeated recovery that computes the same verified
  generation reuses and returns the existing winner idempotently. If a different
  valid generation is already active for the same source identity, preserve the
  evidence and return `publication_conflict`; never choose last-writer-wins or
  silently replace a different result.
- **D-12:** Failure cleanup may delete only the unique staging paths owned by
  that invocation. It must never delete a pre-existing generation, active
  pointer, recovered destination, or quarantine bundle. Complete unreferenced
  generations are harmless and may be handled only by a later bounded,
  ownership-aware garbage-collection policy.

### Exit evidence and claims
- **D-13:** Close `CR-03` with rehashed adversarial archives passed through the
  production verifier. At minimum cover false consent/privacy, invalid IDs and
  event types, unknown packet members, session/world mismatch, capture and
  journal sequence inversion, lifecycle/idempotency contradictions, invalid
  RR-FLOAT/transform values, unsafe paths, and member substitution after
  verification. None may yield a `VerifiedArchive` or expose a replay record.
- **D-14:** Close `CR-04` by routing every existing writer crash boundary through
  production `CaptureRecovery` and capability-only `ReplayCore`, not the
  test-only `scanDurablePrefix` implementation. For every boundary, the recovered
  result must equal the physically fsynced prefix, including the regression in
  which a valid journal record exists beyond the stale manifest projection.
- **D-15:** Close `CR-12` with process-death injection before and after every
  relevant generation/pointer write, file fsync, directory fsync, rename, and
  pointer replacement, plus repeated two-publisher races. Restart must expose
  either the prior active generation or one complete verified winner; repeat
  recovery returns that winner and no loser can delete it.
- **D-16:** A phase verification report may mark only `CR-03`, `CR-04`, and
  `CR-12` closed against the exact reviewed source revision after their focused
  tests and review pass. Phase 2 verification, `GATE-001`, and milestone v1.0
  stay open until the remaining review blockers and genuine device/human
  evidence are closed. Verification of these repairs happens now, not in the
  next milestone; physical evidence is neither required nor fabricated here.

### the agent's Discretion
- Choose exact Swift protocol/type names, access-control layout, and dependency
  injection mechanics while preserving the sole-verifier and opaque-capability
  boundary.
- Choose internal generation directory names and pointer/inventory encoding.
  These internal formats must be closed, versioned, bounded, content-addressed,
  and fully fault-tested; they do not change CON-001 or CON-002.
- Choose deterministic fault-injection harness mechanics and race repetition
  counts sufficient to exercise every named boundary without relying on timing
  luck.

</decisions>

## Existing Code Insights

### Reusable Assets
- `ios/Packages/ReRoomContracts/Sources/ReRoomContracts/ContractValidation.swift`
  already exposes the digest-pinned `ContractValidator` and closed schema
  registry needed by the sole archive verifier.
- `ios/Packages/ReRoomContracts/Sources/ReRoomContracts/FrozenSchemaValidator.swift`
  provides the fail-closed Draft 2020-12 profile behind that public validator;
  recovery should reuse it, not reproduce selected checks.
- `ios/Packages/ReRoomContracts/Sources/ReRoomCaptureCore/FramePacketEncoder.swift`
  already injects `ContractValidator`, establishing the package's dependency
  pattern.
- `ios/Packages/ReRoomContracts/Sources/ReRoomTransactionCore/TransactionStore.swift`
  provides a reusable content-addressed immutable-generation plus active-pointer
  persistence pattern, including inventory verification and idempotent reuse.
- `ios/Packages/ReRoomContracts/Tests/ReRoomCaptureCoreTests/CaptureCrashMatrixTests.swift`,
  `CaptureRecoveryTests.swift`, and `ReplayCoreTests.swift` provide the existing
  fault matrix and replay assertions that must be routed through production
  recovery.

### Established Patterns
- `CaptureArchiveStore` appends and fsyncs each global-journal record before a
  later open-manifest replacement. That ordering is intentional record-first
  durability and must not be inverted merely to hide stale projections.
- `ArchivePath` and bounded reads already support fail-closed archive-relative
  path handling; publication and replay must extend the same no-traversal and
  non-symlink posture.
- The codebase uses typed stable rejection codes, canonical JSON/digests,
  deterministic tests, filesystem adapters, and explicit fault observers.
- Durable state is published through staging, fsync, immutable generations, and
  a last atomic pointer rather than mutating accepted history in place.

### Integration Points
- Replace the partial trust role of `RecoveryArchiveReader` inside
  `CaptureRecovery.verifiedArchive` with the injected complete verifier and
  opaque capability construction.
- Change `ReplayCore.replay(root:)` so production replay consumes only
  `VerifiedArchive`; raw-path inspection remains an admission operation owned by
  `CaptureRecovery`/the verifier.
- Rework `CaptureRecovery.recover` and its filesystem adapter around physical
  journal reconstruction and one generation/pointer publication transaction.
- Update the app's recovery discovery/inspector path to request a verified
  capability and display the prior Phase 2 label **Recovered — capture may be
  incomplete** without treating integrity verification as fixture or gate proof.
- Keep later Phase 7 B0 consumers behind the same verified-capability boundary.

<specifics>
## Specific Ideas

- Treat `VerifiedArchive` as an unforgeable in-process capability, not a boolean
  claim attached to a URL.
- Derive a deterministic recovery generation identity from the complete
  inventory/source binding and accepted-prefix result so unchanged input has one
  idempotent winner.
- Keep `publication_conflict` as the explicit outcome for two different valid
  generations rather than silently choosing a later filesystem writer.
- Preserve the prior user-facing recovery status **Recovered — capture may be
  incomplete**; integrity success must remain distinct from `GATE-001` or frozen
  fixture agreement.

</specifics>
